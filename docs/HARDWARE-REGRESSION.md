## L3 · 动态流程

### 录音 + 电平流（`0xA4=0` → `0xA8`）

| 项 | 实测 |
| :-- | :-- |
| `0x80` 开始 | `state=RECORDING`，生成 `...F525D_20261022151347.mp3` |
| `0xA8` 帧数 | **50 帧**（3 秒，≈16.7 帧/秒） |
| 电平范围 | **-43.1 dB ~ -14.0 dB**（全部在合法区间内） |
| `0x80` 停止 | `state=STOPPED` |

### 录音 + 实时 MP3 流（`0xA4=1` → `0x90`）

| 项 | 实测 |
| :-- | :-- |
| `0x90` 帧数 | **42 帧** |
| 总字节 | **12096 B** = 42 × 288 |
| 每帧长度 | 全部 **288 字节**（按同步头 `FF F3 48 C4` = MPEG-2 Layer III / 32kbps / 16kHz，单帧 144B，即 2×144B = 72ms） |
| MP3 同步头 | 全部 `FF F3 48 C4` |

本采样窗口内共收到 42 帧 ≈ 3 秒，与协议文档「4 秒约 102 帧」的理论值（约 14 帧/秒）不一致；两者帧率口径不同，帧率待确认。低 MTU 重组器未产生错位。

### BLE 文件同步（`0x84`）

| 项 | 实测 |
| :-- | :-- |
| 文件 | `F40E110F525D_20261021183632.mp3` |
| 声明大小 | 4096 B（来自 `0x13` 的 `size` 字段） |
| 实际下载 | **4096 B**（按 `size` 截断填充正确） |
| 耗时 | **242 ms** |
| 两次下载一致性 | **SHA256 相同**（确定性） |
| MP3 同步头 | 存在 |

该链路在原 SKILL 中仅有文档说明、未实现（含缺包重传逻辑），本次已在真机验证通过。

## 新增实证发现（严重程度高于原勘误）

### 1. 固件不校验 CRC，也不校验长度字段

| 实验 | 发送 | 反应 |
| :-- | :-- | :-- |
| 读电量，CRC 双字节异或 | `5A 03 01 3F 7F` | **正常应答** 80% |
| 写休眠超时 600s，CRC 错 | `5A 06 B0 00 58 02 CF 3E` | **返回 success 且 600s 实际写入** |
| 长度字段改错 | `5A 05 01 C0 80` | **正常应答** |

`0x5A` 帧的 CRC16 在该固件上**不具备任何防护作用**。链路上的位翻转会被静默执行。

> `0x9A`（清空全部）在 CRC 错误时的行为未作测试：该操作不可逆，涉及用户数据。依据 `0xB0` 的表现，该风险确实存在。

### 2. 文档的 `0x00` 异常帧从未出现

| 触发 | 文档预期 | 真机 |
| :-- | :-- | :-- |
| CRC 错 | `0x00`+`0x02` | 无视，照常执行 |
| 长度错 | `0x00`+`0x01` | 照常应答 |
| 未定义指令 | `0x00`+`0x04` | **无应答** |
| 热点期间录音 | `0x00`+`0x03` | **无应答** |
| `0x84` 文件不存在 | ack `exists=0x00` | **无应答**（见 ERRATA E11） |

**失败语义是无应答，而非错误帧。** 因此 `MemoTalkTimeout` 才是实际的错误信号。

例外：`0x92` 删除不存在的文件确实返回了文档中的帧 `5A 05 92 00 04 A0 C6`，字节一致。

### 3. `0x87` 存在过渡期锁

一次 enable 被中断后：两次 `0x87` 超时（14s）、`0x87` 关闭返回失败、FTP 显示 `0.0.0.0`（热点实际已关闭），但 **`0x80` 录音被拒绝**。心跳 `0x01` 全程正常，说明链路未断开，是设备状态机停留在以内部标志为准的中间态。约数十秒后**自行恢复**，无需物理按键。

### 复验结果

**L3/L4 第一轮（18:19）**：16 PASS / 1 FAIL。唯一的 FAIL 暴露了 `0x84` 失败帧的解析缺陷。

**修复后 L3（18:27）**：**12 PASS / 0 FAIL**

| 断言 | 修复前 | 修复后 |
| :-- | :-- | :-- |
| `0x84 failure frame parsed` | `ProtocolError: ack is for 'NOT_EXIST_000000.m'` | `exists=False err=0x04 packets=0 size=29 (expect name+9=29)` |
| `0x84 missing -> not found` | 抛 `ProtocolError` | `FileNotFoundOnDevice in 0.1s` |
| `0x84 download`（正常文件） | 12288B / 508ms | 16384B / 631ms，确定性 + MP3 同步头正确 |
| `0x87 hotspot off` | — | `confirmed=True attempts=1` |
| `0x03 confirms off` | — | `hotspot_state=False` |

失败帧现在由设备**立即应答**（0.1s），不再经过 `0x13` 回退路径，说明回退仅作保底，主路径已正确。

## 关于「设备内录音归零」的说明

回归过程中曾观察到设备文件数从 9 变为 0。经用户确认：**这些录音是用户在本次工作之外自行删除的，与本库及本次回归无关。**

该现象不计入回归结论，此处仅保留其中仍然有效的技术观测：文件数为 0 时 `0x13` 返回 `FF 00 05 13 00 00 64 68`，用于验证空列表解析路径（见 ERRATA E11 第 2 条）。
